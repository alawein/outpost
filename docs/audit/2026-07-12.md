## Catalog caveats

The sequence reads coherently start to end (bootstrap -> checks -> releases -> ports in -> ports
out -> rename -> audit -> audit remediation), but the seven-category scheme forces some real
PRs into an imperfect bucket. Named here rather than left as a silent misfit:

- ADRs filed under docs-truth (#19, #22, #62, #83, #105, #116). A decision record is not "a doc
  corrected to match behavior"; it is the closest available bucket to a pure-documentation,
  no-code PR, but the scheme has no separate decision-record category.
- Pure prose/style passes filed under docs-truth (#6, #18, #20, #25, #27, #28, #29, #30, #43,
  #71, #90) carry no factual correction, only wording. Bucketed with docs-truth as the nearest
  fit for a documentation-only PR; a stricter reading of "corrected to match actual behavior"
  would leave them uncategorized.
- #1 is titled like the later release-cut PRs (agi-coding-kit vX.Y.Z) but is not a thin
  version-bump: it is the actual first build of the whole kit. Categorized feature, not release,
  breaking the vX.Y.Z-equals-release pattern the rest of the early sequence holds.
- #91 (v0.23.0, "distill to a pure coding kit") deletes four domain packs and the kit.eval front
  door in one PR that also bumps the version. It is a scope reversal, not a bug fix in the
  ordinary sense; filed as fix for lack of a better bucket (closest to "correcting an
  architectural boundary violation"). #92 (the ACK rename) has the same version-titled,
  substance-bundled shape and is filed process/repo for the same reason (repo-identity match, not
  CODEOWNERS/CI in the literal sense).
- #97, #106, and #101 each bundle a fix, a new gate check, and (for #97) a new prompt in one PR.
  Categorized by the PR's own lead framing (the defect it names first), not by counting lines
  changed per concern.
- #52 both closes a reported drift bug (issue #51) and ships the templates_sync gate check that
  guards the fix; categorized fix since the PR frames itself as closing #51, with the check as the
  regression guard.
- #113 (repo topology simplification: merge build scripts, flatten adapters) is a refactor, not
  literally CODEOWNERS/CI/branch-protection hygiene; filed process/repo as the nearest bucket for
  repo-structure maintenance with no behavior change.
- #48 and #66 each name a doc-truth fix and a gate-check extension in one PR; categorized by
  whichever is the larger or more novel piece of the two (#48 gate/check for the new roadmap
  check, #66 fix for the audit-batch framing).
