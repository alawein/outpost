| 2026-08-15 | risk-review | Second live run, against the branch carrying ADR-0030's original write guard, dispatched after it had already been reviewed clean multiple times and before it merged: attacked its claims instead of just reading them, and broke three. First, the delete side was not actually closed: the byte-match reasoning that seemed to make `--remove`/`--prune` safe against a symlink-redirected delete fails in a real, non-malicious setup (a project whose `.claude/` is a directory symlink to a location shared with another project), since the shared location's content is genuinely the kit's own bytes, not an attacker's. Reproduced end to end: installing into the symlinked project correctly skipped the write, but a later `--remove` in that project still deleted the file at the shared location. Root cause: `main()` computes each path's manifest ownership record before `apply()` later decides, in the same run, to skip that path for escaping containment, so the record step never learns of the skip and records `{"existed": false, "kit_hash": ...}` for the escaped path exactly as it would for a path the kit genuinely wrote; that false record is what let `remove_for_tools`'s byte-match check authorize the delete. A fix that only stops the manifest from recording the false claim proved necessary but not sufficient: `_file_records` deliberately carries every prior install's records forward, so a path installed legitimately, then symlink-escaped, then surviving a narrower `--only`/`--exclude` reinstall keeps its old, now-stale record; reproduced deleting up to 28 real files outside the project this way with a record-time fix alone in place. Second, the "fixed, kit-owned location" reasoning that had scoped `.outpost/manifest.json` out of the original guard was wrong: its write site in `--prune` and its write-or-delete site in `--remove` reproduced escaping through a symlinked `.outpost` directory the same way as any other kit path.
